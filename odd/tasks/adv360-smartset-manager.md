# adv360-smartset-manager

## Objective
Deliver a working, installed, tested Rust application for the Kinesis Advantage360 SmartSet USB keyboard on Omarchy (Arch/CachyOS, Hyprland/Wayland): one reusable core plus two independent interfaces (GTK4 GUI and Ratatui/Crossterm TUI) that share exactly one reader/editor/validator/backup/writer. Objective: let the user configure profiles 1-9 and the 5 documented layers for programming symbols and text navigation, safely, with backups, diffs, validation and undo, and without ever silently losing data from the v-Drive.

## Scope and constraints
AUTHORIZED (user explicitly asked to build and test this on their PC): - Create ~/Projects/personal/advantage360-manager as a Rust workspace (core lib + CLI + TUI + GUI). - Write source, tests, docs, README, install scripts, desktop entry. - Run cargo fmt/clippy/test/release build; install a desktop shortcut and put the TUI command on the user's PATH. - Work-unit commits on branch feat/adv360-smartset-manager (never on a default branch), no AI attribution. - Reversible real-hardware test in a configurable profile WITH backup, only if the keyboard is connected. NON-GOALS / NEVER (hard constraints from the user): - Never modify settings.txt, never reset profiles, never update firmware. - Never write outside the selected profile's layout file(s); never delete unknown/comment lines. - Never run the whole app as root; never write to the v-Drive without an explicit confirmation plus a dated local backup. - No auto-application of a personal layout: the symbol/navigation maps are DRAFTS to be reviewed. - No push, no PR, no merge. ENVIRONMENT EVIDENCE (observed): - CachyOS (Arch-like), kernel 7.1.5-2-cachyos, Wayland display wayland-1, HYPRLAND_INSTANCE_SIGNATURE empty in this shell. - rustc/cargo 1.95.0 stable, target x86_64-unknown-linux-gnu. - GTK4 4.24.1 present via pkg-config; crates.io reachable (ratatui 0.30.2, crossterm 0.29.0, gtk4 0.11.5). - lsusb shows NO Kinesis device; no /run/media/<user>/ADV360. Hardware test is therefore blocked. USER DECISIONS: Linux keyboard layout = English US (QWERTY). Keyboard will NOT be connected during this session; the real reversible hardware test is pending and must be reported as pending, not as passed.

## Route

Delegated bounded writers for the two large independent UI surfaces (TUI, GTK4 GUI) once the core API is frozen - trigger: implementation touching 2+ non-trivial files each, plus the long-session backstop. Delegated bounded writer for the test suite expansion - trigger: preparation of a large independent artifact. Route per task recorded below in the task text.
